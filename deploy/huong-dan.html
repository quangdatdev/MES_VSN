Hướng dẫn chạy MES trên máy chủ

Mã nguồn ở F:\App\MES_VSN, web chạy từ F:\App\MES-run. Mở PowerShell bằng tài khoản Windows đang chạy pm2, chạy các lệnh dưới đây.

1. Cài đặt mớiLàm một lần, lần đầu chuyển sang cách chạy mới 2. Có code mớiLàm mỗi lần cập nhật 3. File cấu hình .envCần những dòng gì, sửa xong làm gì 4. Phiên bản, quay về bản cũXem đang chạy bản nào, lùi khi bản mới lỗi 5. Khi có vấn đềScript báo lỗi, cảnh báo thì làm gì

Hai thư mục trên máy chủ

Mỗi thư mục một việc, không dùng lẫn.

F:\App\MES_VSN
mã nguồn (thư mục git)		 Chỉ để lấy code mới và gõ lệnh triển khai. Web không chạy từ đây. Không sửa file trong thư mục này: có file bị sửa thì lần cập nhật sau script không lấy được code.
F:\App\MES-run
nơi web chạy		 Script tạo và quản lý. Mỗi lần cập nhật là một bản riêng trong releases\. Người vận hành chỉ sửa đúng một file: shared\.env (mục 3).
Vì sao tách hai thư mục? Web đang chạy giữ file trong node_modules và dist, nên cài gói, build ngay chỗ đang chạy thì phải dừng web. Script cài gói, build bản mới trong F:\App\MES-run\releases\<ngày-giờ> trong lúc bản cũ vẫn chạy, xong mới chuyển web sang bản mới trong vài giây.

1. Cài đặt mới

Làm một lần, khi máy chủ còn chạy MES theo cách cũ (pm2 chạy thẳng trong F:\App\MES_VSN). Nên làm ngoài giờ: web sẽ dừng khoảng 1 phút.

  1. Sao lưu 5 database MES_Core, MES_Order, MES_Sewing, MES_Hr, MES_Sync.
  2. Kiểm máy 
    node -v
pm2 -v
pm2 ls
git -C F:\App\MES_VSN status
    Cần thấy: Node v22.x, pm2 7.0.4. Ghi lại tên app MES trong bảng pm2 ls (thường là mes). Dòng cuối phải báo nothing to commit, working tree clean; có file bị sửa thì dừng lại, hỏi người viết code.
  3. Lấy code mới 
    cd F:\App\MES_VSN
git pull --ff-only
    Lần này phải tự lấy để có thư mục deploy\. Từ lần sau script tự làm.
  4. Tạo thư mục chạy, chép cấu hình, khóa quyền Mở PowerShell bằng Run as administrator (cùng tài khoản Windows đang chạy pm2): 
    New-Item -ItemType Directory F:\App\MES-run\shared
Copy-Item F:\App\MES_VSN\backend\.env F:\App\MES-run\shared\.env
icacls F:\App\MES-run /inheritance:r /grant:r "*S-1-5-32-544:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F" "${env:USERDOMAIN}\${env:USERNAME}:(OI)(CI)F"
    • Lệnh icacls: chỉ quản trị máy, SYSTEM và tài khoản của bạn được mở F:\App\MES-run, vì thư mục này chứa mật khẩu database. Ổ F: thường mặc định cho mọi người dùng trong máy đọc được.
    • pm2 chạy bằng tài khoản khác tài khoản đang đăng nhập: thêm tài khoản đó vào cuối lệnh icacls, dạng "<MÁY>\<tài khoản>:(OI)(CI)F".
    • F:\App\MES-run đã có từ trước thì nó phải trống (hoặc chỉ có shared); có thứ khác thì script từ chối chạy.
    Mở file F:\App\MES-run\shared\.env, kiểm đủ các dòng ở mục 3. File cũ thường thiếu NODE_ENV=production.
  5. Chạy Quay lại cửa sổ PowerShell thường (không cần quyền quản trị): 
    cd F:\App\MES_VSN
node deploy\deploy.cjs --root F:\App\MES-run
    Khi hỏi ... Đã sao lưu 5 database chưa? (y/N) thì gõ y rồi Enter. Script build vài phút (web cũ vẫn chạy), rồi dừng web cũ, cập nhật database, chạy bản mới. Thấy dòng Đang chạy: ... và Thời gian web gián đoạn: khoảng ... giây là xong.
    • App cũ tên mes: chạy nguyên lệnh trên, script tự thay app cũ.
    • App cũ tên khác (xem ở bước 2): thêm --replace <tên app cũ> vào cuối lệnh.
    • Bản cũ chạy bằng dịch vụ Windows (NSSM...) thay vì pm2: dừng và gỡ dịch vụ đó trước.
  6. Kiểm tra 
    pm2 ls
cd F:\App\MES_VSN
node deploy\deploy.cjs --root F:\App\MES-run --status
    • pm2 ls: app mes, mode cluster, status online.
    • Kết quả --status có pm2: online (theo ecosystem) và dòng Kiểm sống ...: ok.
    • Mở web, đăng nhập, bấm F5: vẫn còn đăng nhập.
    • File F:\App\MES-run\logs\mes-error.log không có lỗi lúc khởi động.
  7. Tự chạy khi khởi động lại máy Script đã lưu danh sách app mới của pm2 (pm2 save).
    • Máy chủ đang tự bật pm2 bằng pm2 resurrect (Task Scheduler, pm2-installer...): giữ nguyên, không cần làm gì.
    • Cách đang dùng gọi thẳng pm2 start F:\App\MES_VSN\...: đổi thành pm2 resurrect, nếu không thì sau khi khởi động lại máy, web chạy lại bản cũ trong thư mục mã nguồn.
    • Chưa có cách nào: xem phần dưới.
    Tạo tác vụ tự chạy pm2 khi khởi động máy

    Mở PowerShell bằng Run as administrator. Thay <MÁY>, <tài khoản> bằng tài khoản chạy pm2; /RP * sẽ hỏi mật khẩu của tài khoản đó.

    schtasks /Create /TN "MES pm2 resurrect" /SC ONSTART /DELAY 0001:00 /RL HIGHEST /RU "<MÁY>\<tài khoản>" /RP * /TR "C:\Users\<tài khoản>\AppData\Roaming\npm\pm2.cmd resurrect"

    Lệnh này chưa thử trên máy chủ. Thử bằng cách khởi động lại máy ngoài giờ, rồi kiểm như bước 6.

  8. Dọn (không bắt buộc) Sau vài ngày chạy ổn, xóa file cấu hình cũ trong thư mục mã nguồn để mật khẩu database chỉ còn ở một nơi: 
    Remove-Item F:\App\MES_VSN\backend\.env
    Các thư mục node_modules, backend\dist, frontend\dist trong F:\App\MES_VSN cũng không còn dùng. Cứ để đó, không ảnh hưởng gì.
Máy chủ mới hoàn toàn (chưa có gì)?
  • Cài Node.js 22, Git, SQL Server (5 database và login SQL của ứng dụng đã có). Cài pm2: npm install -g pm2@7.0.4
  • Ổ F: phải là ổ NTFS gắn trên chính máy chủ, không phải ổ mạng: script cần tạo liên kết thư mục (junction).
  • Lấy mã nguồn: git clone <địa chỉ repo> F:\App\MES_VSN
  • Bỏ bước 2 phần pm2 ls (chưa có app cũ). Ở bước 4: không có file để chép, bỏ dòng Copy-Item, tạo F:\App\MES-run\shared\.env theo mẫu ở mục 3; vẫn chạy icacls.
  • Sau bước 6: đăng nhập admin bằng mật khẩu DEMO_PASSWORD, tạo tài khoản quản trị riêng, chạy đồng bộ lần đầu. Chi tiết: tài liệu 11-van-hanh.md, mục Cài ứng dụng.

2. Có code mới

Làm mỗi lần có bản mới. Không tự dừng pm2, không tự chạy git pull, npm ci, build: script làm hết.

  1. Chạy một lệnh 
    cd F:\App\MES_VSN
node deploy\deploy.cjs --root F:\App\MES-run
    Script tự git pull, chạy npm ci và npm run build trong thư mục bản mới, chạy npm run migrate, rồi chuyển pm2 sang bản mới. Trong lúc cài gói, build, web vẫn chạy bản cũ.
  2. Nếu script hỏi "Đã sao lưu 5 database chưa?" Nghĩa là bản mới có thay đổi database (script in danh sách dưới dòng Migration mới:). Sao lưu 5 database rồi gõ y, Enter.
    Lúc này web sẽ dừng khoảng 20–60 giây. Nên làm ngoài giờ.
    Nếu người viết code báo bản này chỉ thêm bảng, thêm cột thì thêm --online-migrate vào cuối lệnh ở bước 1: web không dừng (script vẫn hỏi sao lưu).
    Không hỏi gì thì web không dừng chút nào.
  3. Xong Thấy dòng Đang chạy: ... là xong. Báo người dùng bấm F5. Ghi vào sổ vận hành: ngày giờ và dòng Đang chạy: ... (mục 4).

Script chỉ đưa lên những gì người viết code đã commit và push. Bản vừa sửa mà chưa push thì lệnh trên báo Bản đang chạy đã là commit này: gõ n, chờ người viết code push.

3. File cấu hình .env

Máy chủ chỉ có một file cấu hình: F:\App\MES-run\shared\.env. Script tự chép file này vào từng bản. Không sửa bản chép trong F:\App\MES-run\current hay releases\: lần triển khai sau sẽ ghi đè.

Mẫu cho máy chủ chạy http:// trong mạng nội bộ

Thay phần trong dấu < > bằng giá trị thật. Tên 5 database đúng mặc định (MES_Core, MES_Order, MES_Sewing, MES_Hr, MES_Sync) thì không cần ghi.

# Máy dùng thật
NODE_ENV=production
SEED_SAMPLE_DATA=false

# SQL Server: login riêng của ứng dụng, db_owner trên 5 database
DB_HOST=<tên máy hoặc IP SQL Server, không kèm tên instance>
DB_PORT=1433
DB_USER=<login SQL>
DB_PASSWORD=<mật khẩu>

# Nguồn đồng bộ, chỉ đọc view. Database nằm cùng máy SQL Server thì để trống dòng ..._SERVER
DB_TRUNGGIAN_NAME=<database trung gian chứa view BRAVO>
DB_TRUNGGIAN_SERVER=
DB_OSM_NAME=<database OSM có view vOSMDataFty>
DB_OSM_SERVER=
DB_OSM_APP_NAME=<database ứng dụng OSM có view v_OSMData>
DB_OSM_APP_SERVER=

# Ứng dụng
PORT=<cổng mở web, ví dụ 8000>
HOST=0.0.0.0
JWT_SECRET=<chuỗi ngẫu nhiên, ít nhất 32 ký tự>
DEMO_PASSWORD=<mật khẩu ban đầu của admin, ít nhất 8 ký tự>
COOKIE_SECURE=false
TRUST_PROXY=

Từng dòng cần biết

NODE_ENV=productionBắt buộc trên máy chủ: bật các chốt an toàn (bắt buộc JWT_SECRET đủ dài, chặn các lệnh xóa dữ liệu demo). Chỉ ghi trong file này, không đặt thành biến môi trường của Windows. File mẫu backend\.env.example không có dòng này: phải tự thêm.
SEED_SAMPLE_DATA=falseKhông nạp dữ liệu giả; chặn reset:demo, load:bravo, sim:board. Đơn hàng BRAVO tự nạp sau mỗi lần đồng bộ.
JWT_SECRETTạo bằng lệnh dưới rồi chép kết quả vào file. Đặt một lần rồi giữ nguyên: đổi là mọi người bị đăng xuất. 
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
DEMO_PASSWORDMật khẩu ban đầu của admin. Luôn giữ dòng này: lần triển khai nào script cũng chạy migrate, thiếu là dừng. Giữ dòng này không làm đổi mật khẩu admin đã đặt.
COOKIE_SECUREWeb mở bằng http:// (trình duyệt báo "Not secure") thì phải là false. Để sai thì tải lại trang là mất đăng nhập, cứ 15 phút phải đăng nhập lại.
HOST, TRUST_PROXYChạy thẳng như hiện nay: HOST=0.0.0.0, TRUST_PROXY để trống. Khi có HTTPS qua Nginx hoặc IIS trên cùng máy: HOST=127.0.0.1, TRUST_PROXY=loopback, COOKIE_SECURE=true.
Các dòng khác trong file mẫuĐể trống, mặc định đã đúng cho máy chủ. Dòng bật/tắt chỉ nhận true, false hoặc để trống; gõ 0, yes là backend không chạy.

Sửa file xong

  • Thông thường: chạy lệnh dưới. Script kiểm cấu hình trước; sai thì giữ cấu hình cũ, web không bị ảnh hưởng. 
    cd F:\App\MES_VSN
node deploy\deploy.cjs --root F:\App\MES-run --sync-env
  • Đổi các dòng DB_TRUNGGIAN_..., DB_OSM_... (nguồn đồng bộ): phải chạy lại migrate để trỏ sang view mới. Chạy lệnh dưới thay cho --sync-env; khi hỏi Bản đang chạy đã là commit này. Vẫn triển khai lại? thì gõ y. Web không dừng. 
    cd F:\App\MES_VSN
node deploy\deploy.cjs --root F:\App\MES-run --no-pull
    Script không hỏi câu đó mà hỏi sao lưu: F:\App\MES_VSN đang có code mới hơn bản đang chạy, làm như mục 2.

4. Phiên bản, quay về bản cũ

Mỗi lần triển khai là một bản riêng, đặt tên theo ngày giờ. Bản cũ vẫn nằm trên đĩa nên quay về chỉ mất vài giây, không phải build lại.

F:\App\MES-run\
  releases\20261013-160000\   một bản: code đúng commit, đã build, kèm .env
  releases\20261015-180000\
  current                     trỏ vào bản đang chạy
  shared\.env                 file cấu hình duy nhất
  logs\                       mes-out.log, mes-error.log
  ecosystem.config.cjs        cấu hình pm2, script tự chép
  .mes-deploy                 đánh dấu thư mục triển khai, không xóa

Xem đang chạy bản nào

cd F:\App\MES_VSN
node deploy\deploy.cjs --root F:\App\MES-run --status
Kết quả ví dụ, bản mới nhất ở trên: 
Thư mục triển khai: F:\App\MES-run
* 20261020-090000  a1b2c3d Sửa màn Phân bổ PO
  20261015-180000  d4e5f6a Lịch làm việc theo ĐVCS
  20261013-160000  b7c8d9e Cách triển khai mới
pm2: online (theo ecosystem)
Kiểm sống http://127.0.0.1:8000/api/v1/health: ok
  • * là bản đang chạy. Sau tên bản là mã commit và nội dung commit người viết code ghi.
  • Bản có chữ (build xong, chưa chạy được) hoặc (build lỗi hoặc đang làm) là bản hỏng, không dùng để quay về.
  • Kiểm sống ...: không trả lời nghĩa là web không chạy: xem mục 5.

Quay về bản trước

cd F:\App\MES_VSN
node deploy\deploy.cjs --root F:\App\MES-run --rollback
  • Script in bản đang chạy và bản sẽ quay về, rồi hỏi Quay về bản trước?: gõ y, Enter. Thấy Đang chạy: ... là xong, báo người dùng bấm F5.
  • Về bản đã từng chạy được gần nhất trước bản hiện tại. Chạy thêm lần nữa thì lùi tiếp một bản.
  • Bản quay về dùng file shared\.env hiện tại.
  • Bản mới vừa triển khai mà không khởi động được thì script tự quay về (khi lần đó web không phải dừng để cập nhật database), không cần chạy lệnh này.
  • Muốn lên lại bản mới nhất: làm như mục 2.
Database không quay về theo. Code lùi được, nhưng thay đổi database (bảng, cột mới) đã chạy thì ở lại. Nếu bản đang chạy có thay đổi database mà bản cũ không có, trước khi hỏi, --rollback in Cảnh báo: database đã chạy migration mà bản trước không có kèm danh sách file. Gặp cảnh báo này:
  • gõ n để hủy, hỏi người viết code bản cũ có chạy được với database hiện tại không;
  • muốn lùi hẳn thì phải phục hồi bản sao lưu 5 database chụp trước lần triển khai đó, dữ liệu nhập sau lúc sao lưu sẽ mất. Làm cùng người viết code.
Vì vậy: khi script hỏi Đã sao lưu 5 database chưa? thì sao lưu thật, và kiểm kỹ ngay sau khi lên bản mới.

Số bản được giữ

Mặc định giữ 3 bản đã chạy được, bản cũ hơn bị xóa ở lần triển khai sau. Muốn giữ nhiều hơn thì thêm --keep 5 vào lệnh ở mục 2, lần nào cũng thêm: lần nào thiếu thì lần đó dọn về 3 bản.

Về một bản cũ hơn (đã bị xóa)

Build lại từ lịch sử git, mất vài phút như một lần triển khai. Xem danh sách commit, lấy mã ở đầu dòng: 
cd F:\App\MES_VSN
git log --oneline -20
node deploy\deploy.cjs --root F:\App\MES-run --ref <mã commit hoặc tag>
Cách này không cảnh báo về database như --rollback. Bản còn giữ thì dùng --rollback; về bản cũ hơn nữa thì hỏi người viết code trước.

Để dễ theo dõi

  • Mỗi lần triển khai hoặc quay về, ghi vào sổ: ngày giờ, tên bản (dòng Đang chạy: ...), lý do.
  • Người viết code: ghi nội dung commit rõ ràng (tránh Update), gắn tag cho bản đưa lên máy chủ (git tag v1.0 rồi git push --tags). Khi đó quay về chỉ cần --ref v1.0.

Script báo Cảnh báo: F:\App\MES-run cho Everyone, Authenticated Users, Users truy cậpThư mục chứa mật khẩu DB đang mở cho mọi người trong máy đọc. Mở PowerShell bằng Run as administrator, chạy lệnh icacls mà script in ra (giống bước 4 của mục 1).
Script báo Lệnh lỗi ... git ... pull --ff-onlyThư mục F:\App\MES_VSN có file bị sửa, hoặc lệch với bản trên git. Chạy lệnh dưới, gửi kết quả cho người viết code; không tự xóa, sửa file. Bản đang chạy không bị ảnh hưởng.
git -C F:\App\MES_VSN status
Script báo Đang có lần triển khai khác (... deploy.lock ...)Mỗi lúc chỉ chạy được một lần. Kiểm không còn cửa sổ nào đang chạy script (lần trước bị tắt ngang cũng để lại file này), rồi xóa file F:\App\MES-run\deploy.lock và chạy lại.
Lần đầu, script báo F:\App\MES-run đã có nội dung (...) mà không phải thư mục triển khaiThư mục chạy phải trống hoặc chỉ có shared\.env. Chuyển các file lạ ra chỗ khác rồi chạy lại.
Script báo Có tiến trình đang trả lời ở ... mà pm2 chưa có app "mes"Web cũ chạy bằng app pm2 tên khác hoặc bằng dịch vụ Windows. Làm theo ghi chú ở bước 5 của mục 1.
Thông báo khácĐọc dòng Lỗi: script in ra, thường có ghi cách xử lý. Chi tiết: tài liệu 11-van-hanh.md, mục Cập nhật bản mới lên máy chủ.

Chạy các lệnh bằng đúng tài khoản Windows đang chạy pm2. Không sửa file trong F:\App\MES-run\current hay releases\, không xóa file .mes-deploy, không sửa file trong F:\App\MES_VSN.
