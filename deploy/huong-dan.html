Hướng dẫn chạy MES trên máy chủ

Ví dụ dưới đây: mã nguồn (thư mục git) ở D:\MES, web chạy từ D:\MES-run. Máy chủ để chỗ khác thì đổi đường dẫn cho đúng. Mở PowerShell, chạy các lệnh dưới đây.

1. Cài đặt mớiLàm một lần, lần đầu chuyển sang cách chạy mới 2. Có code mới (git pull)Làm mỗi lần cập nhật 3. File cấu hình .envCần những dòng gì, sửa xong làm gì 4. Phiên bản, quay về bản cũXem đang chạy bản nào, lùi khi bản mới lỗi
Vì sao có thêm thư mục D:\MES-run? Web đang chạy giữ file trong node_modules và dist, nên npm ci, build ngay tại D:\MES thì phải dừng web (như cách cũ). Script cài gói và build bản mới ở thư mục riêng D:\MES-run\releases\<ngày-giờ> trong lúc bản cũ vẫn chạy, xong mới chuyển web sang bản mới trong vài giây. D:\MES chỉ còn dùng để git pull.

1. Cài đặt mới

Làm một lần. Nên làm ngoài giờ: web sẽ dừng khoảng 1 phút.

  1. Sao lưu 5 database MES_Core, MES_Order, MES_Sewing, MES_Hr, MES_Sync.
  2. Lấy code mới 
    cd D:\MES
git pull
  3. Tạo thư mục chạy, chép file cấu hình 
    mkdir D:\MES-run\shared
copy D:\MES\backend\.env D:\MES-run\shared\.env
    Mở file vừa chép, kiểm đủ các dòng ở mục 3. File cũ thường thiếu NODE_ENV=production.
  4. Chạy 
    node deploy\deploy.cjs --root D:\MES-run
    Khi hỏi Đã sao lưu 5 database chưa? thì gõ y rồi Enter. Chờ vài phút tới khi thấy dòng Đang chạy: ... là xong.
    Script tự dừng app pm2 cũ tên mes và tạo app mới. Nếu app cũ tên khác (xem bằng pm2 ls), thêm --replace <tên app cũ> vào cuối lệnh.
  5. Kiểm tra 
    pm2 ls
    Thấy app mes, cột status là online. Mở web, đăng nhập thử.
    Nếu trước đây máy chủ đã tự bật pm2 khi khởi động lại máy thì giữ nguyên, không cần làm gì thêm.
Máy chủ mới hoàn toàn (chưa có gì)?

Trước bước 1, làm thêm:

  • Cài Node.js 22, Git, SQL Server (5 database và tài khoản SQL đã có).
  • Cài pm2: npm install -g pm2@7.0.4
  • Lấy mã nguồn: git clone <địa chỉ repo> D:\MES
  • Ở bước 3: không có file để chép, tạo D:\MES-run\shared\.env theo mẫu ở mục 3.

2. Có code mới (git pull về để chạy)

Làm mỗi lần có bản mới. Không tự dừng pm2, không tự chạy npm ci, build: script làm hết.

  1. Chạy một lệnh 
    cd D:\MES
node deploy\deploy.cjs --root D:\MES-run
    Script tự git pull, chạy npm ci và npm run build trong thư mục bản mới, chạy npm run migrate, rồi chuyển pm2 sang bản mới. Trong lúc cài gói, build, web vẫn chạy bản cũ.
  2. Nếu script hỏi "Đã sao lưu 5 database chưa?" Nghĩa là bản mới có thay đổi database. Sao lưu 5 database rồi gõ y, Enter.
    Lúc này web sẽ dừng khoảng 20–60 giây. Nên làm ngoài giờ.
    Nếu người viết code báo bản này chỉ thêm bảng, thêm cột thì thêm --online-migrate vào cuối lệnh ở bước 1: web không dừng.
    Không hỏi gì thì web không dừng chút nào.
  3. Xong Thấy dòng Đang chạy: ... là xong. Báo người dùng bấm F5. Ghi vào sổ vận hành: ngày giờ và dòng Đang chạy: ... (mục 4).

3. File cấu hình .env

Máy chủ chỉ có một file cấu hình: D:\MES-run\shared\.env. Script tự chép file này vào từng bản. Không sửa bản chép trong D:\MES-run\current: lần triển khai sau sẽ ghi đè.

Mẫu cho máy chủ chạy http:// trong mạng nội bộ

Thay phần trong dấu < > bằng giá trị thật. Tên 5 database đúng mặc định (MES_Core, MES_Order, MES_Sewing, MES_Hr, MES_Sync) thì không cần ghi.

# Máy dùng thật
NODE_ENV=production
SEED_SAMPLE_DATA=false

# SQL Server: login riêng của ứng dụng, db_owner trên 5 database
DB_HOST=<tên máy hoặc IP SQL Server, không kèm tên instance>
DB_PORT=1433
DB_USER=<login SQL>
DB_PASSWORD=<mật khẩu>

# Nguồn đồng bộ, chỉ đọc view. Database nằm cùng máy SQL Server thì để trống dòng ..._SERVER
DB_TRUNGGIAN_NAME=<database trung gian chứa view BRAVO>
DB_TRUNGGIAN_SERVER=
DB_OSM_NAME=<database OSM có view vOSMDataFty>
DB_OSM_SERVER=
DB_OSM_APP_NAME=<database ứng dụng OSM có view v_OSMData>
DB_OSM_APP_SERVER=

# Ứng dụng
PORT=<cổng mở web, ví dụ 8000>
HOST=0.0.0.0
JWT_SECRET=<chuỗi ngẫu nhiên, ít nhất 32 ký tự>
DEMO_PASSWORD=<mật khẩu ban đầu của admin, ít nhất 8 ký tự>
COOKIE_SECURE=false
TRUST_PROXY=

Từng dòng cần biết

NODE_ENV=productionBắt buộc trên máy chủ: bật các chốt an toàn (bắt buộc JWT_SECRET đủ dài, chặn các lệnh xóa dữ liệu demo). Chỉ ghi trong file này, không đặt thành biến môi trường của Windows. File mẫu backend\.env.example không có dòng này: phải tự thêm.
SEED_SAMPLE_DATA=falseKhông nạp dữ liệu giả; chặn reset:demo, load:bravo, sim:board. Đơn hàng BRAVO tự nạp sau mỗi lần đồng bộ.
JWT_SECRETTạo bằng lệnh dưới rồi chép kết quả vào file. Đặt một lần rồi giữ nguyên: đổi là mọi người bị đăng xuất. 
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
DEMO_PASSWORDMật khẩu ban đầu của admin. Luôn giữ dòng này: lần triển khai nào script cũng chạy migrate, thiếu là dừng. Giữ dòng này không làm đổi mật khẩu admin đã đặt.
COOKIE_SECUREWeb mở bằng http:// (trình duyệt báo "Not secure") thì phải là false. Để sai thì tải lại trang là mất đăng nhập, cứ 15 phút phải đăng nhập lại.
HOST, TRUST_PROXYChạy thẳng như hiện nay: HOST=0.0.0.0, TRUST_PROXY để trống. Khi có HTTPS qua Nginx hoặc IIS trên cùng máy: HOST=127.0.0.1, TRUST_PROXY=loopback, COOKIE_SECURE=true.
Các dòng khác trong file mẫuĐể trống, mặc định đã đúng cho máy chủ. Dòng bật/tắt chỉ nhận true, false hoặc để trống; gõ 0, yes là backend không chạy.

Sửa file xong

  • Thông thường: chạy lệnh dưới. Script kiểm cấu hình trước; sai thì giữ cấu hình cũ, web không bị ảnh hưởng. 
    cd D:\MES
node deploy\deploy.cjs --root D:\MES-run --sync-env
  • Đổi các dòng DB_TRUNGGIAN_..., DB_OSM_... (nguồn đồng bộ): phải chạy lại migrate để trỏ sang view mới. Chạy lệnh dưới thay cho --sync-env; khi hỏi Bản đang chạy đã là commit này. Vẫn triển khai lại? thì gõ y. Web không dừng. 
    cd D:\MES
node deploy\deploy.cjs --root D:\MES-run --no-pull
    Script không hỏi câu đó mà hỏi sao lưu: D:\MES đang có code mới hơn bản đang chạy, làm như mục 2.

4. Phiên bản, quay về bản cũ

Mỗi lần triển khai là một bản riêng, đặt tên theo ngày giờ. Bản cũ vẫn nằm trên đĩa nên quay về chỉ mất vài giây, không phải build lại.

D:\MES-run\
  releases\20261013-160000\   một bản: code đúng commit, đã build, kèm .env
  releases\20261015-180000\
  current                     trỏ vào bản đang chạy
  shared\.env                 file cấu hình duy nhất
  logs\                       mes-out.log, mes-error.log

Xem đang chạy bản nào

cd D:\MES
node deploy\deploy.cjs --root D:\MES-run --status
Kết quả ví dụ, bản mới nhất ở trên: 
* 20261020-090000  Sửa màn Phân bổ PO
  20261015-180000  Phase 1 : Done
  20261013-160000  Cách triển khai mới
pm2: online (theo ecosystem)
  • * là bản đang chạy. Chữ sau tên bản là nội dung commit người viết code ghi.
  • Bản có chữ (build xong, chưa chạy được) hoặc (build lỗi hoặc đang làm) là bản hỏng, không dùng để quay về.

Quay về bản trước

cd D:\MES
node deploy\deploy.cjs --root D:\MES-run --rollback
  • Script in bản đang chạy và bản sẽ quay về, rồi hỏi Quay về bản trước?: gõ y, Enter. Thấy Đang chạy: ... là xong, báo người dùng bấm F5.
  • Về bản đã từng chạy được gần nhất trước bản hiện tại. Chạy thêm lần nữa thì lùi tiếp một bản.
  • Bản quay về dùng file shared\.env hiện tại.
  • Bản mới vừa triển khai mà không khởi động được thì script tự quay về (khi bản đó không đổi database), không cần chạy lệnh này.
  • Muốn lên lại bản mới nhất: làm như mục 2.
Database không quay về theo. Code lùi được, nhưng thay đổi database (bảng, cột mới) đã chạy thì ở lại. Nếu bản đang chạy có thay đổi database mà bản cũ không có, trước khi hỏi, --rollback in Cảnh báo: database đã chạy migration mà bản trước không có kèm danh sách file. Gặp cảnh báo này:
  • gõ n để hủy, hỏi người viết code bản cũ có chạy được với database hiện tại không;
  • muốn lùi hẳn thì phải phục hồi bản sao lưu 5 database chụp trước lần triển khai đó, dữ liệu nhập sau lúc sao lưu sẽ mất. Làm cùng người viết code.
Vì vậy: khi script hỏi Đã sao lưu 5 database chưa? thì sao lưu thật, và kiểm kỹ ngay sau khi lên bản mới.

Số bản được giữ

Mặc định giữ 3 bản đã chạy được, bản cũ hơn bị xóa ở lần triển khai sau. Muốn giữ nhiều hơn thì thêm --keep 5 vào lệnh ở mục 2, lần nào cũng thêm: lần nào thiếu thì lần đó dọn về 3 bản.

Về một bản cũ hơn (đã bị xóa)

Build lại từ lịch sử git, mất vài phút như một lần triển khai. Xem danh sách commit, lấy mã ở đầu dòng: 
cd D:\MES
git log --oneline -20
node deploy\deploy.cjs --root D:\MES-run --ref <mã commit hoặc tag>
Cách này không cảnh báo về database như --rollback. Bản còn giữ thì dùng --rollback; về bản cũ hơn nữa thì hỏi người viết code trước.

Để dễ theo dõi

  • Mỗi lần triển khai hoặc quay về, ghi vào sổ: ngày giờ, tên bản (dòng Đang chạy: ...), lý do.
  • Người viết code: ghi nội dung commit rõ ràng (tránh Update), gắn tag cho bản đưa lên máy chủ (git tag v1.0 rồi git push --tags). Khi đó quay về chỉ cần --ref v1.0.

node deploy\deploy.cjs --root D:\MES-run --rollback
