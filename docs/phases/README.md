# Kế hoạch chia phase – MES Vietsun

Mục đích: chia nhỏ để **review từng giai đoạn** trước khi đi tiếp. Quy tắc: mỗi phase kết thúc ở trạng thái chạy được; AI dừng lại chờ duyệt, không tự sang phase sau (xem `CLAUDE.md` mục 2).

**Review code:** cuối mỗi phase, trước khi chuyển `Ready for review`, agent `code-reviewer` review mọi file của phase theo `docs/review/README.md` (khoảng 0,25 ngày/phase). Còn phát hiện `CRITICAL`/`HIGH` thì chưa chuyển trạng thái. Báo cáo: `docs/review/phase-<N>.md`.

Trạng thái: `Not started` · `In progress` · `Ready for review` · `Approved` · `Blocked`

## Quan hệ giữa các phase

```
P0 chốt ─► P1 backend ─┬─► P3 phân quyền động ─► P4 hoàn thiện demo ─► (duyệt, xin tài khoản AI) ─► P5
                       └─► P2 frontend ──────────┘
```
P1 và P2 có thể làm song song sau khi hợp đồng API (P0) đã chốt.

## Điều đã chốt (tham chiếu nhanh)

- Mục tiêu đợt này: **Demo giao diện + thể hiện phân quyền**. Tài liệu BA gửi sau.
- Mỗi module một database; `MES_Core` chứa `Sys*`; `MES_Order` chứa module Đơn hàng (thay `MES_Demo` từ 09/10/2026).
- Nhà máy mã `A01`, `A02`…, cấm sửa mã, sửa được tên; `A00` = tổng hợp (xem tất cả, chỉ đọc).
- Phân quyền: đủ 5 lớp từ 09/10/2026 – Role × Menu × hành động, lọc `BranchCode`, phạm vi theo phép gán (nhà máy, chuyền, người tạo), ẩn/che/chỉ đọc theo cột, ngoại lệ theo người có hạn dùng (ADR 0005, 0006).
- Công nghệ: NestJS + Kysely + SQL Server; React + Mantine (ADR 0003).
- Tài khoản MES riêng, chưa SSO. Chỉ dùng dữ liệu giả; chưa kết nối BRAVO/OSM/GSD.
