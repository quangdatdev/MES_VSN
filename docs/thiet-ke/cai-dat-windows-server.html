Cài đặt MES lên Windows Server 10.0.0.216

Các bước cài, script linked server sang BRAVO_TRE (10.0.0.225), tên tài khoản cần thống nhất, và những ảnh hưởng có thể xảy ra. Viết ngày 11/10/2026 theo code hiện tại.

Giả định: SQL Server của MES cài cùng máy 10.0.0.216; BRAVO_TRE nằm trên instance mặc định của 10.0.0.225, cổng 1433.

Người dùng → http://10.0.0.216:3000 (Node, MES) → SQL Server .216 bằng mes_user → MES_Sync: stored → synonym bravo.src_* → linked server LS_BRAVO → 10.0.0.225 bằng mesvsn_user → view trong BRAVO_TRE

2. Stored đang nối vào đâu

  • Cả 18 thủ tục chép bravo.usp_Sync_<Bảng> chỉ đọc nguồn qua synonym bravo.src_<Bảng>. Không thủ tục nào ghi tên máy hay tên database BRAVO. Vì vậy chỉ cần thống nhất một đầu nối là synonym; đổi đích thì tạo lại synonym, không sửa stored.
  • Thủ tục điều phối dbo.usp_SyncRun_Execute được backend gọi bằng mes_user, nên linked server dùng ánh xạ của mes_user. Không thủ tục nào dùng EXECUTE AS.
  • Thủ tục đọc nguồn vào bảng tạm trước BEGIN TRANSACTION, nên đọc qua linked server không cần MSDTC (giao dịch phân tán).

Đã gỡ (11/10/2026, cách A): trước đây npm run migrate chỉ tạo synonym 3 phần [BRAVO_TRE].[dbo].[view] (hàm linkSyncSources trong backend/scripts/migrate.ts). Cách này chỉ chạy khi BRAVO_TRE cùng máy với MES_Sync. Trên .216 cần synonym 4 phần [LS_BRAVO].[BRAVO_TRE].[dbo].[view]. Chọn một trong hai cách:

Cách A (đã có, dùng cách này): đặt DB_TRUNGGIAN_NAME=BRAVO_TRE và DB_TRUNGGIAN_SERVER=LS_BRAVO trong .env; mỗi lần npm run migrate tự tạo lại synonym 4 phần, kể cả sau khi tạo lại database MES_Sync. ADR 0007 đã tính trước bước này.

Cách B (cũ, không cần nữa): để trống DB_TRUNGGIAN_NAME (migrate sẽ bỏ qua bước synonym), rồi chạy script ở bước C6.

Còn chờ bạn chốt: ghi chú bổ sung cho ADR 0007 (hay ADR mới) về việc đọc BRAVO_TRE qua linked server tới chính máy .225 đang chứa B8R2_VIETSUN; việc "không đọc B8R2" khi đó dựa vào quyền của mesvsn_user trên .225.

3. Các bước

A. Máy 10.0.0.225 Quản trị CSDL bên BRAVO

  1. Tạo login chỉ đọc cho MES: 
    -- Chạy trên SQL Server 10.0.0.225 bằng tài khoản quản trị
USE master;
CREATE LOGIN mesvsn_user WITH PASSWORD = N'<mật khẩu mạnh>',
  DEFAULT_DATABASE = BRAVO_TRE, CHECK_POLICY = ON, CHECK_EXPIRATION = OFF;
GO
USE BRAVO_TRE;
CREATE USER mesvsn_user FOR LOGIN mesvsn_user;
ALTER ROLE db_datareader ADD MEMBER mesvsn_user;
  2. Cho view đọc được bảng B8R2_VIETSUN mà không cấp quyền đọc thẳng (chuỗi sở hữu giữa hai database; hai database phải cùng chủ sở hữu, view và bảng cùng schema dbo): 
    ALTER DATABASE BRAVO_TRE    SET DB_CHAINING ON;
ALTER DATABASE B8R2_VIETSUN SET DB_CHAINING ON;
GO
USE B8R2_VIETSUN;
CREATE USER mesvsn_user FOR LOGIN mesvsn_user;   -- không thêm role, không GRANT gì
GO
-- 4 view gọi hàm ufn_Agg_Concat (vDM_KHACHHANG, vDM_DiaDiemGiaoHang, vThongTinPO, vThongTinPO_MauCo).
-- Nếu vẫn lỗi 229 "EXECUTE permission", cấp quyền trên hàm ở database chứa hàm:
-- GRANT EXECUTE ON dbo.ufn_Agg_Concat TO mesvsn_user;
  3. Mở tường lửa cho .216 vào cổng 1433: 
    New-NetFirewallRule -DisplayName "SQL tu MES 216" -Direction Inbound -Protocol TCP -LocalPort 1433 -RemoteAddress 10.0.0.216 -Action Allow
  4. Gửi mật khẩu mesvsn_user cho quản trị CSDL bên MES bằng kênh riêng, không qua tài liệu.

B. SQL Server trên 10.0.0.216 Quản trị CSDL bên MES

  1. Cài SQL Server 2019 hoặc 2022, chế độ đăng nhập Mixed Mode, collation SQL_Latin1_General_CP1_CI_AS. Trong SQL Server Configuration Manager: bật TCP/IP, cổng 1433 (bản Express mặc định tắt TCP/IP).
  2. Tạo 5 database và mes_user: 
    USE master;
CREATE DATABASE MES_Core;
CREATE DATABASE MES_Order;
CREATE DATABASE MES_Sewing;
CREATE DATABASE MES_Hr;
CREATE DATABASE MES_Sync;
GO
CREATE LOGIN mes_user WITH PASSWORD = N'<mật khẩu mạnh>',
  DEFAULT_DATABASE = MES_Core, CHECK_POLICY = ON, CHECK_EXPIRATION = OFF;
GO
USE MES_Core;   CREATE USER mes_user FOR LOGIN mes_user; ALTER ROLE db_owner ADD MEMBER mes_user;
GO
USE MES_Order;  CREATE USER mes_user FOR LOGIN mes_user; ALTER ROLE db_owner ADD MEMBER mes_user;
GO
USE MES_Sewing; CREATE USER mes_user FOR LOGIN mes_user; ALTER ROLE db_owner ADD MEMBER mes_user;
GO
USE MES_Hr;     CREATE USER mes_user FOR LOGIN mes_user; ALTER ROLE db_owner ADD MEMBER mes_user;
GO
USE MES_Sync;   CREATE USER mes_user FOR LOGIN mes_user; ALTER ROLE db_owner ADD MEMBER mes_user;
  3. Kiểm .216 tới được .225: Test-NetConnection 10.0.0.225 -Port 1433 phải ra TcpTestSucceeded : True.
  4. Tạo linked server LS_BRAVO: 
    USE master;
-- Xem driver có sẵn: MSOLEDBSQL (bản 18) hoặc MSOLEDBSQL19 (bản 19)
EXEC master.dbo.xp_enum_oledb_providers;

EXEC sp_addlinkedserver @server = N'LS_BRAVO', @srvproduct = N'',
     @provider = N'MSOLEDBSQL', @datasrc = N'10.0.0.225';
-- @datasrc: named instance thì ghi N'10.0.0.225\TEN_INSTANCE' hoặc N'10.0.0.225,<cổng>'
-- Driver bản 19 bắt buộc mã hóa: .225 không có chứng chỉ hợp lệ thì thêm
--   @provstr = N'Encrypt=Mandatory;TrustServerCertificate=Yes'

EXEC sp_serveroption N'LS_BRAVO', N'data access', N'true';
EXEC sp_serveroption N'LS_BRAVO', N'rpc', N'false';
EXEC sp_serveroption N'LS_BRAVO', N'rpc out', N'false';     -- không gọi thủ tục bên .225
EXEC sp_serveroption N'LS_BRAVO', N'remote proc transaction promotion', N'false';
EXEC sp_serveroption N'LS_BRAVO', N'use remote collation', N'true';
EXEC sp_serveroption N'LS_BRAVO', N'connect timeout', N'30';
EXEC sp_serveroption N'LS_BRAVO', N'query timeout', N'3600';  -- mặc định 600 giây; chép lại toàn bộ view lớn qua mạng có thể lâu hơn

-- Bỏ ánh xạ mặc định "mọi login dùng chính mình", chỉ cho mes_user đi qua
EXEC sp_droplinkedsrvlogin @rmtsrvname = N'LS_BRAVO', @locallogin = NULL;
EXEC sp_addlinkedsrvlogin @rmtsrvname = N'LS_BRAVO', @useself = N'FALSE',
     @locallogin = N'mes_user', @rmtuser = N'mesvsn_user', @rmtpassword = N'<mật khẩu mesvsn_user>';
  5. Đăng nhập SSMS bằng mes_user rồi thử: 
    SELECT TOP (5) * FROM LS_BRAVO.BRAVO_TRE.dbo.vDM_CHINHANH;      -- phải ra dữ liệu
SELECT TOP (5) * FROM LS_BRAVO.BRAVO_TRE.dbo.vThongTinPO;       -- view gọi ufn_Agg_Concat, phải ra dữ liệu
SELECT COUNT(*) FROM LS_BRAVO.B8R2_VIETSUN.INFORMATION_SCHEMA.TABLES;  -- phải ra 0: không thấy bảng BRAVO
    Đăng nhập bằng một login khác (không phải mes_user) chạy câu đầu: phải bị từ chối.

C. Ứng dụng trên 10.0.0.216 Nhóm phát triển

  1. Cài Node.js 22 LTS bản x64. Kiểm: node -v ra v22.x.
  2. Chép mã nguồn vào D:\MES. Không chép node_modules, frontend\dist và backend\.env của máy dev.
  3. Tạo D:\MES\backend\.env: 
    NODE_ENV=production
PORT=3000
HOST=0.0.0.0
DB_HOST=localhost
DB_PORT=1433
DB_USER=mes_user
DB_PASSWORD=<mật khẩu mes_user>
# Tên database để mặc định: MES_Core, MES_Order, MES_Sewing, MES_Hr, MES_Sync
DB_TRUNGGIAN_NAME=BRAVO_TRE
# BRAVO_TRE ở máy .225, đọc qua linked server: migrate tạo synonym [LS_BRAVO].[BRAVO_TRE].[dbo].[view]
DB_TRUNGGIAN_SERVER=LS_BRAVO
JWT_SECRET=<chuỗi ngẫu nhiên, tạo bằng lệnh dưới>
COOKIE_SECURE=false
TRUST_PROXY=
DEMO_PASSWORD=<mật khẩu mạnh, seed hiện bắt buộc>
# Không nạp đơn hàng giả, phòng ban và nhân viên giả (NODE_ENV=production đã mặc định như vậy, ghi rõ cho chắc)
SEED_SAMPLE_DATA=false
    NODE_ENV=production chỉ đặt trong backend\.env, không đặt thành biến môi trường của Windows: khi đó npm ci bỏ các gói dùng để build, npm run build và migrate hỏng. Tạo JWT_SECRET: node -e "console.log(require('crypto').randomBytes(48).toString('hex'))". Chỉ tài khoản quản trị Windows được đọc thư mục backend.
  4. Cài gói và build (cần ra được Internet tới npm registry): 
    cd D:\MES
npm ci
npm run build
  5. Tạo bảng, thủ tục và nạp dữ liệu hệ thống: npm run migrate. Phải thấy cả 5 database báo đã chạy migration, rồi dòng "Nạp dữ liệu hệ thống và tài khoản admin". Lệnh tạo nhà máy, vai trò, quyền, menu, danh mục, loại phòng ban, chức danh dùng chung và một tài khoản admin (mật khẩu DEMO_PASSWORD); không có tài khoản mẫu, đơn hàng giả, nhân viên giả. Vẫn có nhà máy A01–A03, xưởng và chuyền mẫu: sửa tên, ngừng dùng ở màn Danh mục hệ thống cho đúng thực tế.
  6. Synonym qua linked server.
    • Cách A: migrate ở bước 5 đã tạo, bỏ qua bước này.
    • Cách B: đăng nhập SSMS bằng mes_user, chạy: 
      USE MES_Sync;
DECLARE @sql NVARCHAR(MAX) = (
  SELECT STRING_AGG(CAST(
           N'IF OBJECT_ID(N''' + s.SourceSynonym + N''', N''SN'') IS NOT NULL DROP SYNONYM '
         + QUOTENAME(PARSENAME(s.SourceSynonym, 2)) + N'.' + QUOTENAME(PARSENAME(s.SourceSynonym, 1)) + N'; '
         + N'CREATE SYNONYM ' + QUOTENAME(PARSENAME(s.SourceSynonym, 2)) + N'.' + QUOTENAME(PARSENAME(s.SourceSynonym, 1))
         + N' FOR [LS_BRAVO].[BRAVO_TRE].[dbo].' + QUOTENAME(s.SourceObject) + N';'
         AS NVARCHAR(MAX)), NCHAR(10))
  FROM dbo.SyncSource s WHERE s.SystemCode = N'BRAVO');
EXEC sys.sp_executesql @sql;
SELECT name, base_object_name FROM sys.synonyms ORDER BY name;  -- 18 dòng, đều bắt đầu bằng [LS_BRAVO]
  7. Đăng nhập admin bằng DEMO_PASSWORD. Không tài khoản nào tự đổi được mật khẩu của mình, nên: tạo tài khoản quản trị riêng (vai trò Quản trị hệ thống) ở màn Người dùng, đăng nhập bằng tài khoản đó rồi vô hiệu hóa admin; hoặc đổi DEMO_PASSWORD trong .env rồi chạy npm run seed -- --reset-passwords (chỉ đổi mật khẩu admin). Tạo tài khoản người dùng thật ở màn Người dùng. Không cần chạy npm run seed trên server. Migrate báo "Cảnh báo: admin chưa…" thì chạy npm run seed -- --sync-matrix.
  8. Cài dịch vụ Windows bằng NSSM (tải ở nssm.cc), để MES tự chạy khi khởi động máy và tự chạy lại khi lỗi: 
    nssm install MES "C:\Program Files\nodejs\node.exe" D:\MES\backend\dist\main.js --serve-web
nssm set MES AppDirectory D:\MES\backend
nssm set MES AppStdout D:\MES\logs\mes.log
nssm set MES AppStderr D:\MES\logs\mes.log
nssm set MES AppRotateFiles 1
nssm set MES AppRotateBytes 10485760
nssm set MES Start SERVICE_AUTO_START
nssm start MES
    Tạo thư mục D:\MES\logs trước.
  9. Mở cổng cho người dùng (PowerShell quyền Administrator): 
    New-NetFirewallRule -DisplayName "MES 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow
  10. Chép dữ liệu lần đầu, ngoài giờ làm việc: đăng nhập admin, vào Quản trị › Đồng bộ dữ liệu, bấm "Chép lại toàn bộ".

D. Kiểm tra sau khi cài

  1. http://10.0.0.216:3000/api/v1/health trả {"status":"ok"} (chỉ cho biết tiến trình còn sống).
  2. Từ máy khác và từ điện thoại cùng mạng mở http://10.0.0.216:3000, đăng nhập, chọn nhà máy, tải lại trang vẫn còn phiên.
  3. Màn Đồng bộ dữ liệu: 18 nguồn "Thành công". Bấm chép tăng dần lần hai: chạy nhanh, số dòng đọc ít.
  4. Trên .225 xem câu lệnh mesvsn_user gửi sang (Activity Monitor › Recent Expensive Queries hoặc sys.dm_exec_query_stats): câu đọc dòng mới phải có WHERE … ModifiedAt. Không có nghĩa là mỗi lần đều kéo cả view qua mạng.
  5. Khởi động lại máy .216: MES tự lên, không cần đăng nhập Windows.
  6. Job backup chạy thành công ít nhất một lần, đã thử restore sang database khác.
